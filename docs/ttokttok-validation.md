# 똑똑 로컬 웹 검증과 롤백

## 출시된 범위

`/ttokttok/app/`은 한 브라우저의 IndexedDB에 기록을 저장합니다. 직접 입력한
계량기 기록과 청구 기간, 추정 표시, 공급사 공식 사이트 열기, JSON 백업
가져오기와 내보내기, 개인 정보가 없는 주간 캘린더 파일을 제공합니다. 공급사
로그인, 계약 조회, 청구서 조회, 검침 제출, 제출 성공 표시는 제공하지 않습니다.

백업은 암호화된 보관소가 아닙니다. 공개 Android schema 1–4를 검증해 가져오고,
현재 내보내기는 schema 4입니다. 인증정보와 자동 제출 동작은 내보내지 않습니다.

## 자동 검증과 실기기 검증의 구분

2026-09-19 로컬 검증에서 기존 사이트 Python 테스트 35개, 도메인·저장소 테스트
25개와 Chromium, Android 화면 크기, iPhone WebKit의 브라우저 테스트 48개가
통과했습니다. 브라우저 테스트에는 저장 후 재시작, 저장 실패와 재시도, 탭 간
변경 충돌, 백업 후 저장소 삭제와 복원, 새 버전 적용과 오프라인 실행이 포함됩니다.
WebKit 오프라인 검증은 자동화 도구의 오프라인 전환 대신 테스트 서버를 종료해
실제 요청 실패 상태에서 수행합니다. Android 백업 호환성은 고정된 upstream
공개 codec 규격과 합성 예시를 대조한 결과이며 실제 Android 기기에서 파일을
양방향 이동한 실사용 검증과 구분합니다.

자동 브라우저 검증은 코드와 정적 셸의 회귀를 찾기 위한 것입니다. 다음 항목은
자동 결과로 확인되었다고 기록하지 않습니다.

실제 iPhone에서 Safari와 홈 화면 앱을 각각 열어 다음을 확인합니다.

1. Safari에서 기록을 입력하고 닫았다 다시 열어 기록이 남는지 확인합니다.
2. Safari에서 JSON 백업을 내보내고 파일 앱에서 존재와 내용을 확인합니다.
3. 홈 화면 앱에서 같은 절차를 별도로 수행합니다. Safari와 홈 화면 앱의 저장
   공간은 분리될 수 있으므로 서로의 기록이 보인다고 가정하지 않습니다.
4. 각 환경에서 JSON 가져오기, 일반 다운로드 또는 공유 시트, 그리고 `.ics`
   내려받기와 구독 링크의 캘린더 handoff를 확인합니다.
5. 오프라인으로 다시 열고, 새 버전 안내가 있을 때 저장하지 않은 입력을
   버리지 않고 취소할 수 있는지 확인합니다.

이 체크리스트는 물리 기기에서 아직 실행되지 않은 항목을 완료로 바꾸지 않습니다.

## 롤백

롤백 전 현재 `ttokttok/app/` 정적 파일과 배포 revision을 기록합니다. 이전 정적
셸로 되돌릴 때도 브라우저의 `ttokttok-web-v1` IndexedDB를 삭제하거나 service
worker에서 정리하지 않습니다. 배포 후에는 기존 schema 1–4 백업을 가져올 수
있는지 확인하고, 현재 기록을 먼저 JSON으로 내보낼 수 있는지 확인합니다.

롤백이 새 형식을 읽지 못할 위험이 있으면 먼저 현재 셸에서 백업을 내보내도록
안내하고, 호환되는 정적 셸을 준비할 때까지 데이터 저장소를 변경하지 않습니다.
